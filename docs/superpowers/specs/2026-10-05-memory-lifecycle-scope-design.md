# gitev 设计补充：读写时机与本地范围隔离

日期：2026-10-05。状态：用户同意将 claude-mem 调研结论补入设计；当前只有设计文档，没有核心库、CLI、宿主 hooks 或实验结果。

本文补充 [先导核心设计](2026-09-28-pilot-core-cli-design.md)。发生冲突时，读写时机及多范围边界以本文为准，七类维护操作、校准、待审、幂等与失败语义继续沿用核心设计。用户已选择先做本地多项目、多设备范围隔离，同步后置；设备在首版是本地登记的适用范围，不代表已实现跨电脑传输。

## 1. 调研依据与设计取舍

2026-10-05 核对 claude-mem `main` 提交 `bfc50259f64a4e0c9e81df849095683608e87ac8`，属于源码调研，未安装或运行验证。

| 方案 | 取舍 |
| --- | --- |
| 仅在轮次结束抽取、会话启动注入 | 接入简单，但明确纠正处理迟、会话中范围变化后容易继续用旧上下文 |
| 事件先接收，显式维护及时处理，普通内容合批；启动与按需召回配合（采用） | 复用现有事件/提案/条目模型，能测试纯聊天、恢复与可见性；不要求每轮模型调用 |
| 完整复制宿主插件、worker 与向量检索服务 | 接入能力丰富，但增加部署和宿主生命周期依赖，留到核心验证后 |

claude-mem 的 [hooks](https://github.com/thedotmack/claude-mem/blob/bfc50259f64a4e0c9e81df849095683608e87ac8/plugin/hooks/hooks.json) 将输入、工具观察、总结和上下文分别处理；[本地事件交接](https://github.com/thedotmack/claude-mem/blob/bfc50259f64a4e0c9e81df849095683608e87ac8/src/cli/spool-hook-event.ts) 先持久化待处理文件，再通知后台。其 [默认配置](https://github.com/thedotmack/claude-mem/blob/bfc50259f64a4e0c9e81df849095683608e87ac8/src/shared/SettingsDefaultsManager.ts) 关闭每轮语义注入，裸用户输入默认随后续工具事件处理；总结请求也能启动处理，不能据此推定纯聊天必然丢失。

首版采用独立核心库与 CLI，生命周期通过输入事件和显式调用重放。本文中的宿主事件名称用于后续映射，不表示首版安装这些 hooks。常驻服务、Chroma、完整插件、自动整理与同步均不增加为先导前置条件。

## 2. 捕获、维护与摘要的边界

继续使用输入事件、变更提案、记忆条目三种业务对象。事件是来源证据，提案是拟执行变更，条目表达当前状态；摘要是可重建的派生输出，不增加另一套权威事实源。

```text
允许留存的输入 → 接收记录持久化 → 事实/维护意图抽取
                              → 所属范围内候选 → 规则 / LLM / Jev
                              → 提案与确定性校验 → 完整 Git 提交
已提交的可见范围快照 → 当前有效事实与提示 → 按需展开证据/历史
```

接收前先按显式留存标记和排除范围过滤；调用凭据只从配置读取，禁止作为事件内容保存。明确不保存的片段不进入事件、Git、模型请求或日志；过滤后无可处理内容时返回忽略，不调用模型。首版使用构造场景，不承诺自动识别所有未标记的真实敏感信息。事件只保存允许留存且处理所需的内容；截断必须显式记录，不能声称保存了完整证据。业务撤回继续保留历史，不代表物理擦除。

捕获成功只表示事件已接收，不表示已形成有效事实。来源必须区分用户陈述、助手建议、工具观察与转述；助手声称“部署成功”不能替代执行证据，工具失败不能直接推出环境事实失效。

“沉默是默认”适用于无长期价值的新事实抽取，不用于丢弃纠正、撤回或阶段状态。未完成事项和阶段总结可保存为有任务关联及时间条件的内容，不自动提升为个人长期习惯，也不建设第二套任务管理系统。

## 3. 写入机会与恢复

| 触发 | 接收与处理规则 | 首版验证方式 |
| --- | --- | --- |
| 用户输入 | 先接收；来源及说话者明确；没有工具调用也进入处理流程 | 自然语言 ingest 与纯聊天序列 |
| 明确记住、纠正、撤回 | 接收后立即进入维护流程；显式 ID 撤回走确定性规则，模糊目标待审 | 维护事件与 review |
| 普通轮次、工具成功/失败 | 先接收允许的证据，轮次结束处理尚未处理内容；不逐个工具强制调用模型 | 结构化事件、批次边界 |
| 长任务阶段完成 | 处理本阶段未处理事件，生成有来源的进展及未完成事项摘要 | 阶段边界事件 |
| 会话结束 | 尝试处理剩余事件；不把结束回调作为唯一持久化机会 | 结束边界与恢复重放 |
| 进程恢复 | 按原 ID 重试已接收且未完成/失败的事件；不重复应用成功结果 | 中断与重复输入测试 |

Claude Code 的 [Stop 是每轮回答结束](https://code.claude.com/docs/en/hooks#stop)，SessionEnd 才是会话结束；宿主适配不能混淆两者。宿主回调来不及执行或没有送达时，核心无法凭空恢复未接收内容，须由适配器报告缺口，不能宣称“异步即不丢失”。

用户显式维护请求必须返回接收 ID 及已应用、待审或失败状态，不能只报告“已记住”。立即处理不绕过校准、范围、证据、版本与合法转移检查。模型失败保留为失败；待审不改变原有效值。轮次结束的重复处理复用事件 ID 与已保存结果。

CLI 首版 ingest 可直接接收单条或同一所属范围的有序批次并处理，不依赖后台常驻进程。批次边界只划定处理机会，不提供跨事件原子性；每个事件保留独立结果。恢复调用从接收记录继续，抽取与网络调用仍在写锁外。

## 4. 读取机会与预算

| 触发 | 返回内容 |
| --- | --- |
| 会话启动、恢复、上下文压缩后 | 当前范围说明、少量有效默认、相关未完成事项和冲突/待审提示 |
| 新任务、历史经验问题 | 与查询相关的当前事实，按需展开来源 |
| 操作相关文件或对象前 | 必要的决策背景和约束；文件历史由后续宿主适配提供 |
| 写入、人工裁决、范围切换后 | 基于新提交重建视图，防止复用旧缓存 |

启动注入、按需读取均复用 recall；核心无须自动监控会话或推断用户切换了项目。调用方必须提供当前项目、设备及可选任务上下文；生活问题可只选择个人范围，不被迫绑定项目。

采用 [claude-mem 的分层检索思路](https://github.com/thedotmack/claude-mem/blob/bfc50259f64a4e0c9e81df849095683608e87ac8/plugin/skills/mem-search/SKILL.md)：先返回简短索引，再展开选中条目及必要的来源时间线，最后才读取原始证据。普通查询只列有效事实，历史查询单独标记旧值、撤回和失效；时间线不能将旧事实重新提升为当前答案。

每次返回携带 memory_id、所属范围、状态、来源和快照版本。索引、时间线、按 ID 展开、history 都检查相同的允许范围，知道一个 ID 不能绕过过滤。任何模型请求只包含允许范围内的输入与候选；不能先全库检索再由模型判断是否可见。

条目数和输出预算由调用参数及评测 manifest 固定，报告截断和省略数。复用相同范围、查询、模式、预算与提交版本的结果时可去重；范围或任一有关提交变化即失效。缓存是可删除、可重建的派生物，首版可以不设缓存，使用关键词检索也不强制向量服务。

## 5. 本地多项目、多设备范围与版本

记忆只有一个所属范围；来源设备与适用设备分别记录。来自 Mac 的项目通用约定可以属于项目范围，Mac 路径才属于设备或项目设备范围。项目和设备使用显式稳定 ID，路径只作为绑定线索，不直接用同名文件夹或当前源码 HEAD 充当身份。

| 所属范围 | 适用内容 | 记忆仓库中的建议分支 |
| --- | --- | --- |
| `personal` | 个人背景、跨项目习惯 | `master` |
| `device(device_id)` | 该设备的通用环境 | `devices/<device_id>` |
| `project(project_id)` | 同项目在不同设备上的通用约定 | `projects/<project_id>/shared` |
| `project_device(project_id, device_id)` | 项目在指定设备的路径、配置 | `projects/<project_id>/devices/<device_id>` |

分支是独立记忆仓库中的范围版本载体，不是用户源码分支。Git 父提交不提供动态继承；创建范围不得把父范围条目复制成该范围所属条目。分支到范围的绑定须唯一且通过 Git ref 校验，不接受模型自行构造分支路径。

项目 A 在设备 M 上的视图按允许范围组合 personal、device(M)、project(A)、project_device(A,M)，排除其他项目及设备。任务上下文用于筛选有关内容；首版不为每个任务创建 Git 分支。明确选择个人模式时只读取 personal，不隐式加入当前项目私有内容。

短写锁内固定本次各范围的 ref@commit，随后从这些 Git 对象读取；一个读取期间不混入后续提交。判断与提案记录其实际依赖的快照集合，应用前校验有关范围版本，而不仅检查写入分支。单写入者发布一份所属范围内的完整变更；跨范围操作须拆成显式请求，不承诺多分支原子事务。

范围组合保留原条目身份及来源。明确的项目约定可覆盖适用的个人默认，但个人默认仍在其范围有效；同主题而适用条件不同的事实并存。无法解释的冲突按冲突组呈现，不能仅凭“分支更具体”或记录较新就选择真值。

对继承条目修改或删除时，入口必须显式选择影响范围和目标 ID，不能隐式改动个人原记忆。项目范围的新增约定可以表达本地覆盖；首版不提供含糊的“删除继承记忆”快捷操作，也不将本地屏蔽误称为全局撤回。专用覆盖/屏蔽操作及其便捷默认需另行设计确认，本次不增加第八类维护操作。

跨范围提升需要显式指定新的所属范围并留下来源关系；首版不做自动提升、git merge 自动裁决知识或跨电脑同步。多设备测试在一台机器上以两个 device_id 重放，只证明本地隔离规则。

## 6. 生活与编程内容的有效期

| 输入 | 存储及读取语义 |
| --- | --- |
| “我已搬到上海” | 明确主体与生效时间后维护现居地，旧地址留在历史 |
| “以后推荐餐厅优先清淡” | 个人长期偏好；不依赖工具事件 |
| “今天想吃火锅” | 当前轮次需求；通常不形成长期偏好 |
| “周五要出差” | 若需跨会话保留，附明确日期及有效条件；相对时间按事件时间解释 |
| “本轮测试通过” | 绑定项目、源码版本及执行证据；不推出后续版本也通过 |
| “阶段二尚未完成” | 绑定任务与来源，后续进展可更新，不成为个人长期事实 |

短期跨会话信息可以有保存价值，不以“一周以后是否相关”作为所有内容的强制门槛。编程内容的“能否从代码发现”是减少冗余的参考，不能用于排除生活偏好。缺少到期条件时只复核，不凭记忆年龄自动失效。

## 7. 评测与验收补充

保留先导 60 条意图和 24 个生命周期序列、编程/生活各半；调整覆盖矩阵，不将所有触发点与范围做笛卡尔积。确定性恢复/隔离测试另计，不作为更多独立语义样本。

必须覆盖：纯生活对话无工具调用；显式纠正后紧接召回；轮次结束重复提交；接收后处理前中断；提交后返回前中断；项目 A/B 切换；设备 M/N 切换；同名路径绑定不同项目 ID；详情及历史越界读取；依赖范围更新使旧提案失效；旧缓存失效；阶段状态不升级为长期事实。

| 指标 | 定义或报告要求 |
| --- | --- |
| 接收遗漏率 | 协议要求接收但无持久记录的事件 / 全部应接收事件；只测核心时不归因于宿主 hook |
| 处理遗漏率 | 截至规定边界无已保存处理结果的事件 / 全部已接收且应处理事件；待审、忽略及已记录失败均是结果，失败率单列 |
| 变更可见延迟 | 分别记录接收、处理开始、提交、首次返回新视图时间；待审及失败不伪造成功延迟 |
| 越界返回率 | 返回的范围外条目 / 全部返回条目；另报出现越界的请求数及有效召回 |
| 上下文代价 | 索引、详情、历史分别记录输出量、重复注入量、实际 token 或字符计量、模型调用与费用 |

时序与范围测试和语义判断测试分开报告。规则/LLM/Jev 内部对照共享事件、触发规则、可见范围及预算；模型自己的状态分化继续保留。若后续将 claude-mem 纳入外部对照，先冻结提交、配置、输入映射和支持矩阵，作为整体系统比较，不将其与 gitev 的全部差异归因于 Jev。

首版验收是核心/CLI 在这些模拟生命周期中行为正确；真实宿主捕获完整性、注入生效和实际多电脑同步需要后续独立验证。以前 4–6 人日先导及完整报告估算基于较小范围，不能直接承诺覆盖本次增量。
